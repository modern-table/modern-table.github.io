# Modern Table: instructions for Claude sessions working in this repo

Repository `modern-table/modern-table.github.io` (the `modern-table` GitHub organization). The game is served by GitHub Pages from `main` at the repo root as https://modern-table.github.io/, so whatever `index.html` is on `main` is what players get. Moved here on 2026-10-17 from an older address, which now only forwards players here and carries their saved decks over (`#import=` in the URL, read by `IMPORTED` in both pages). Keep the project's public face free of personal names: commits are authored by Claude, and nothing in the repo, the pages or the README should name the maintainer.

**Project notes:** each release adds its entry to the end of the Project doc `claude/modern-table-notes-v4.118-on.md` (the current notes file since 2026-11-10) and updates its "Current setup (as of …)" line. To write it back, save the whole updated text to a file inside the working directory and pass it to `project_write` as `local_path`, rather than pasting it as `content`. Archived and never rewritten: `claude/modern-table-notes-v4.102-on.md` (v4.102–v4.117), `claude/modern-table-notes-v4.88-on.md` (v4.88–v4.101), `claude/modern-table-notes.md` (how the table works, v4.0–v4.87; too long for the project tool to write back) and `claude/modern-table-history-v1-v3.md`. When the current file passes about 40 KB, close it: start `claude/modern-table-notes-<next version>-on.md` with its Current setup section carried over, list the closed file among the archives at the top of the new one, and change the file name here. Don't leave "pending" notes docs; if the current file can't be written back, roll over instead.

## Layout
- `src/app.src.html`: game source (single page; placeholders `/*__DECKS__*/[]` and `/*__PEERJS__*/` are filled by the build).
- `src/decks.txt`: built-in decklists (format below).
- `src/peerjs.min.js`: vendored PeerJS.
- `src/cards.json`: Scryfall data for every card in `src/decks.txt` (plus the tokens they make, keyed `id:<scryfall id>`), built into `index.html` as `BAKED` so the tournament decks need no Scryfall lookups (since v3.42). Written by `tools/make_cards.py <oracle-cards.json>` from Scryfall's Oracle Cards bulk file. The sandbox cannot reach Scryfall, so don't write it by hand: the **Build card data** workflow (`.github/workflows/cards.yml`) regenerates it, rebuilds and pushes whenever `src/decks.txt` changes, every day at 13:23 UTC (retrying when Scryfall answers 5xx), and on "Run workflow". Its commits are by github-actions[bot]. Cards missing from it (new decks before the workflow has run, pasted decks) are still looked up at runtime. The workflow's notice lists names it could not find: a card a decklist calls by another name (Arena's "Through the Omenpaths" names for Marvel cards, e.g. Kavaero, Mind-Bitten = Superior Spider-Man) goes in `src/aliases.txt`, and the game also reads that file for pasted decks. Cards from decks we paste and play (not tournament lists) can be listed in `src/extra.txt` (decklist format); the workflow builds them in too.
- `build.py`: `python3 build.py` writes `index.html`. It drops any deck with fewer than 60 main or more than 15 sideboard cards and refuses to build with fewer than 10 valid decks.
- `index.html`: generated. Never hand-edit; always rebuild and commit it together with the `src/` change.
- **Line comments end the line.** Much of the source is long one-line statements with trailing `// …` notes. When inserting code into such a line, put it before the `//`, never after: anything after a `//` is part of the comment and silently never runs (v4.37 disabled the city's blessing this way; found in v4.55). `build.py` prints `WARNING: … code after a // comment never runs` for lines that look like this; treat any such warning as a bug.
- `src/draft.src.html` → `draft/index.html`: the Draft Table (see below). Also generated by `build.py`, which copies it to `night/`, `sealed/` and `cube/` too (see Game Night) and writes `night/decks.json`.
- `draft/sets/*.json`, `tools/make_draft_sets.py`: booster odds per set for the Draft Table.

## Versioning
`const VERSION = 'v4.NN'` in `src/app.src.html` (v4.0 on 2026-10-21: the table runs the match, with game losses, a round clock, a sideboarding timer and end-of-round turns; v3.0 on 2026-10-15 brought auto-pay from the mana pool, v3 ran to v3.78; v2.0 on 2026-10-14 marked the table resolving rules itself, v2 ran to v2.06; v1 ran to v1.99). Bump NN by one for any feature or behaviour change: v4.0 → v4.01 → v4.02 … Do NOT bump it for a decks-only refresh.

With every version bump, add one line at the top of the `NEWS` array in `src/app.src.html` (`['v4.NN','Mon D','what changed']`). It feeds the "What's new" list on the front page and in the table menu, and is written for players: plain language, no function names.

## Draft Table (`/draft/`)
Booster draft for up to 8 players; bots fill empty seats. Its own version: `const VERSION = 'v0.NN'` in `src/draft.src.html`, bumped the same way. With every bump add a line at the top of `DNEWS` (same file, right under `VERSION`; `['v0.NN','Mon D','what changed']`, written for players): it fills the front page's What's new column (latest six, "See all changes" shows the rest in place). Draft lines don't go to Discord.
- **Hub model:** the host's browser holds the whole draft (`H`), generates every pack and sends each player only their own view (`V`: current pack, picks, pod status, tournament). Guests send `join`, `pick`, `ready`, `result`. Host state is saved in localStorage (`dt_host`) so a reload resumes; guests rejoin their seat by a stored player id (`dt_pid`).
- **Pack odds:** `draft/sets/<set>.json`, generated by `python3 tools/make_draft_sets.py /path/to/sealed_basic_data.json` from https://github.com/taw/magic-sealed-data (weighted pack layouts and sheets; cards are `set:collector_number`, `:foil` suffix for foils). To add a set, add its booster code to `SETS` in that script, rerun it, rebuild. Sets whose draft works differently (Commander Legends, Conspiracy, Unstable, Mystery Booster) are deliberately left out.
- **Cubes:** a pasted cube list goes, cleaned to one card name per line, in `draft/cubes/<code>.txt`; `python3 tools/make_cube.py <code> "Name" draft/cubes/<code>.txt` writes `draft/sets/<code>.json` (`cube:1`, `names`) and lists it under "Cubes" in `index.json` (`make_draft_sets.py` keeps those entries). A cube is shuffled once per draft and dealt in packs of 15 without repeats; cards are looked up by name (ids `n|Card Name`); names Scryfall can't find are left out and the host sees a notice. Bots ignore rarity in a cube.
- **Archetype guides (v0.28):** `draft/cubes/<code>-archetypes.json` (`name`, `credit`, `list: [{n, c, d, k}]`: name, colors as `WUBRG` letters (empty = any colors), description in American English, key card names exactly as in the cube's list). `build.py` lists the cubes that have one in `GUIDES` (`/*__GUIDES__*/[]`) and prints a WARNING for any key card not in `draft/cubes/<code>.txt`. `openGuide(code)` shows `#guide` (z-index 75, under `#zoom`): color filter (archetypes using every selected color, plus any-color ones), cards, key cards as `.gk[data-zid="n|Name"]` (looked up with `ensure`, so the hover enlargement works; ✓ `.mine` when already in your picks). Opened from the Cube Table's front page (`[data-guide]` choices) and the top bar's `#guideBtn` whenever `V.set` has a guide (all players, every phase). Since v0.29 it is also laid out inline in the lobby (`lobbyGuideHTML()` under the setup / waiting text, for the host and every player who has joined, its own filter `LSEL` via `[data-lgc]`, Open larger carries the filter into the window); `loadGuide(code)` fetches each guide once for both, and `guideFilt` / `guideGrid` draw both. Esc or the backdrop closes it. `CUBE_BY` (next to `GUIDES`) names each cube's maker, credited on the Cube Table's front page credits, in the cube setup text and in the guide's credit line: DF07's Legacy Cube, list and archetype descriptions, is by DackFayden07 (credited at the maintainer's request). DF07's guide was written from the cube designer's own archetype notes (shortened and reworded); its Goblin Bombardment isn't in our copy of the list, so it's not a key card.
- **Offered sets (v0.13):** the set picker shows only the codes in `READY` near the top of `src/draft.src.html` (Reality Fracture, Final Fantasy, MH2, MH1, Khans and the DF07 cube: the ones whose cards the Modern Table plays fully). The other set files stay in `draft/sets/` and `index.json`; add a code to `READY` when its cards are done.
- **Cards:** fetched from Scryfall `/cards/collection` by set and collector number, cached per set in `dt_cards`. **Built-in card data (v0.35):** `ensure` first loads `draft/cards/<code>.json` (`loadBaked`, written by the Build card data workflow's `tools/make_draft_cards.py` from Scryfall's bulk file plus a search per set). A cube's cards (`n|` ids) come straight from it, no lookup. A set's card does too when the file has that printing in `prints` (`[scryfall id, rarity letter, back face 0/1]`, pictures built by `scryImg`); otherwise Scryfall is asked and, if that fails, `fromBaked` fills the card from the file's text and another printing's picture with `bk:1` (rarity from the set's sheet names, `sheetRarity`), retried every 5 minutes. Once a lookup fails, the rest of that `ensure` call skips Scryfall (`down`). Found on 2026-11-11, when Scryfall answered card lookups with "Offline for Maintenance" (503) and cube drafts showed blank cards. `cardHTML` pictures carry `onerror="imgFail(this)"`: a failed picture becomes the text tile (`txtHTML`), and that address isn't tried again for 2 minutes (`IMGBAD`, `imgBad`); the hover enlargement skips it too.
- **Hand-off to the Modern Table:** the deck is saved into the shared `mt_decks` list as text lines `N Card Name [id:<scryfall id>]`; `parseDeck` in `src/app.src.html` reads that suffix so the exact printing is used in play. Match links are `../?t=CODE&r=h|g&d=1` (open or join that table and show the newest saved deck); `?r=s&d=1` is practice. Both pages must stay on the same site so they share browser storage.
- **Basic land art (v0.15):** the deck builder's land row starts with a Basic land art select (`BASIC_ART`, same list as the Modern Table's `BASIC_SETS`). It reads and writes `mt_settings.basics`, the Modern Table's own setting (the pages share storage), so the Modern Table's `loadDeck` applies it when the drafted deck is played; the draft page only shows thumbnails (`dt_basicart`, looked up once through `sfetch`). Keep the two lists in step when a basic style is added.
- **Sealed / prerelease (v0.16):** `H.mode` is `'draft'` or `'sealed'` (front page: Host a draft / Host a prerelease; the setup screen's Format select switches it). Sealed has no bots, no timer and up to 8 players: `startSealed(set)` gives each seat `s.kit = {packs:[[u…]×6], promo:u}` and puts every card in `s.pool` at once (`KIT_PACKS`), then goes straight to `phase:'build'`, so the Swiss rounds, Ready, hand-off and "Start a new event" are the draft's own. `promoFor(set)` draws the promo from the set's `rare…` sheet at its odds, one entry per card name at its lowest collector number, traditional foil, flagged `promo` (PROMO tag); cubes get none. **Since v0.28 only sets in `PRE_SETS` (`['fra']`, the one prerelease kit we know) get a promo and are called a prerelease** (`isPre(code)`: Start the prerelease, "Prerelease: …" title, Your kit tab); every other set's sealed event is six packs with no promo (Start the event, "Sealed: …", Your packs). Add a set to `PRE_SETS` only once its real prerelease kit is worked out. The Draft Table (draft/) hosts drafts only: its Format select and Host a prerelease choice are gone; sealed is hosted from sealed/. Opening is client-side only (`B.op`: `opened`, `promo`, `showing`, `built`, saved with the build in `dt_build`): `kitHTML()` draws the kit box, six wrappers and the promo face down (`BACK_IMG`, the Modern Table's card back), a pack fans out in pack order (`.fan`, rares glow), Sort into my pool, then piles (`pilesHTML(cards, B.grp)`: colour / mana value / type / rarity, `GROUPS`). Build your deck shows the usual build screen with the sideboard pane called Pool, laid out in piles, and every card starting there. Cards move between panes by click (any device) or mouse drag (`DRAG`, pointer events on `[data-zone]`; works in drafts too).
- **Color dive (v0.17; visible text in American English since v0.21, rail buttons are mana symbols too):** `diveRailHTML()` puts five colour buttons beside the build screen's Pool (sealed) / Sideboard (draft) pane (`.poolwrap`); `B.dive` (saved with the build) opens `diveHTML()`, a fixed `#dive` window inside `#main`: every pool card of that colour by `inColour(d, k)` (its colours, so hybrid and gold count for each; colourless non-land cards in every colour (v0.18); lands by `landMakes(d)`: basic land types, "Add {…}" symbols, "any color"), creatures and other spells in mana-value columns 0–1 … 7+, lands in a row. Cards in the deck get `.indk` (green edge, IN DECK); a click toggles like elsewhere. `diveBulk(true|false)`: Bulk add / Take all out for that colour. Mana-symbol buttons in the window header (`data-dive-to`, `manaSym(k)`: Scryfall's symbol SVG over a letter pip) switch colour without closing; the grid's row-label column is `min-content` with `justify-content:start` so cards line up from the left (v0.20). Close ✕ or Esc.
- **Pack images:** `draft/packs/<set>/index.json` (`boosters`: wrapper files, `kit`: the Prerelease Pack box) and WebP files, written by the **Pack images** workflow (`.github/workflows/pack_images.yml`, `tools/get_pack_images.py`) from Wizards' WPN product-shot zip listed in `tools/pack_images.txt` (the sandbox can't reach media.wizards.com; `listing.txt` shows the zip's contents). A kit's covers are dealt evenly by `kitCovers(K, n)` (v0.24: each cover equally often, order shuffled by a hash of the kit's first card, `coverOf`); before, each pack hashed its own first card and the host's seat never drew the Liliana cover. Sets without images get drawn wrappers. Since v0.31 the kit box image shows only for `isPre` sets, so a set whose zip has a Prerelease Pack (Final Fantasy) shows only its wrappers. Sets with images: FRA, FIN (v0.31), MH1 (v0.32: three covers from pictures the maintainer supplied, turned upright, background cleared and committed by hand to `draft/packs/mh1/`; KTK (v0.33) the same way, five covers, the fourth cut from a picture of all five; MH2 (v0.34) the same way, three covers (an extra pass peels the light grey halo a screenshot's background leaves at the edge); not in `tools/pack_images.txt`, so the workflow never touches them). A set without a zip can get wrappers the same way: portrait WebP files `booster-N.webp` (about 320 px wide, transparent background) plus `index.json` with `kit: ""`. Older sets (MH2, MH1, KTK) have no WPN product-shot zip; only single press images or retailer photos turned up (2026-11-11). To add a set: add its line (zip URL from the set's WPN product page, "Product Shots") and push.
- **PeerJS** is loaded from `../src/peerjs.min.js`, not inlined, to keep the page small.
- **Testing:** needs a local PeerServer (`npm i peer`, `PeerServer({port:9000, path:'/', host:'127.0.0.1'})`), the repo served over http, and `?peerhost=127.0.0.1:9000&peersecure=0`. ## decks.txt format
```
# comment lines start with #
@@ Event name|YYYY-MM-DD|tournament id|place|Archetype|Pilot|deck id
4 Card Name
...
Sideboard
2 Card Name
```
One `N Card Name` per line, exact card names, split cards as `Wear // Tear` (MTGTop8 writes `Wear/Tear`; `parseDeck`, `tools/make_cards.py` and `tools/cost_check.py` all read a single slash as ` // `, since v4.104). No `Deck`/`Companion` label lines (a companion is already in the sideboard). No `|` inside a field. Place is `1st`, `2nd`, ...

## Weekly deck refresh (what the Monday scheduled task does)
Goal: replace `src/decks.txt` with top finishers from Modern events of the last 14 days on MTGGoldfish, rebuild, commit, push to `main`.
1. Search: WebFetch `https://www.mtggoldfish.com/tournament_searches/create?tournament_search%5Bname%5D=&tournament_search%5Bformat%5D=modern&tournament_search%5Bdate_range%5D=MM%2FDD%2FYYYY+-+MM%2FDD%2FYYYY&commit=Search` (14 days ago to today). First page only.
2. Pick up to 6 events, newest first: Challenges, Super Qualifiers, Showcases, large paper events. Skip Leagues.
3. For each, WebFetch `https://www.mtggoldfish.com/tournament/ID` for the first 8 rows: place, deck name, pilot, deck id.
4. Choose at most 36 decks: every distinct archetype once first (highest finish), then remaining top-4 finishers.
5. Fetch lists from `https://www.mtggoldfish.com/deck/arena_download/DECKID` (`/deck/download/` is robots-blocked; `/deck/ID` has no list in its HTML). ONE AT A TIME, never in parallel, at most 4 per turn. On HTTP 429 do not retry that page; stop fetching after the second refusal and use what you have. The shell cannot reach mtggoldfish; only WebFetch can.
6. Keep decks from the existing `src/decks.txt` that are still within the last 14 days and were not re-fetched, so a rate-limited week does not shrink the list. Drop decks older than 14 days only if at least 20 decks remain without them.
7. Write `src/decks.txt`, run `python3 build.py`, check its last line reports at least 10 decks and none unexpectedly dropped.
8. Commit `src/decks.txt` and `index.html` (the Build card data workflow then adds the new decks' cards to `src/cards.json` and rebuilds by itself, a few minutes after the push) with message `Weekly deck refresh YYYY-MM-DD (N decks)` and push to `main`. If the push is refused, do not try other routes; report it.
Colour-code archetype names from MTGGoldfish (WU, UR, WBG) may be replaced with a plain name only when the list makes it obvious.

## Auto-pay (v3.0)
With `S.autoPay` on (the default; ☰ menu toggle), `castSpellNow` and `activate` work out the cost (`castSyms`/`abilSyms`), plan it from the pool (`payPlan`) and either pay at once or open `#payPanel`, which waits while lands are tapped; the card stays in its zone until paid. Alternative costs pass `payCost` (warp, dash, flashback, madness, bestow, harmonize with `less`, Mystical Dispute), `castAlt` pays first, free casts pass `nm`. Mana with a restriction or rider goes to `G.me.smana` (its own row under the pool) and is spent only where `specRule` allows. Since v4.99 auto-pay never spends it by itself: `payFor` opens the window whenever `specFor(ctx)` lists special mana that could pay, and `payPlan` uses only the entries the player clicked into the payment (`PAY.ch.sp`, toggled by `spToggle` from the window's Special mana row or the pool symbol); an alternative-cost button carries the picks on through `G.paySel`. Old tests that cast by hand should set `S.autoPay=false` after the page loads.

## Scryfall requests
Scryfall allows 2 card lookups a second (`/cards/collection`, `/cards/named`, `/cards/search`) and locks a client out for 30 s after a 429 (https://scryfall.com/docs/api/rate-limits). Every request goes through `sfetch` (both pages): one queue, 0.55 s apart, 15 s timeout, 31 s pause and one retry after a 429. Never call `fetch` on api.scryfall.com directly. Images (`cards.scryfall.io`) have no limit.

## Testing
Add `&nobake` to the URL in tests that mock Scryfall, so the built-in card data does not replace the mock's cards.
The page needs Scryfall and a PeerJS broker at runtime, which the cloud sandbox cannot reach. For a smoke test, load `index.html` in the pre-installed Chromium with Playwright, mock `api.scryfall.com/cards/collection`, and check the deck screen lists the decks and a solo game starts.
**Cost lines:** `python3 tools/cost_check.py "Card Name" …` (or `--file names.txt`, `--all` for src/cards.json, `--draft` for draft/cards) serves the repo's `index.html` on a free local port, opens a practice game in headless Chromium and asks the game's own readers about every cost line of those cards: "This spell costs …" (`costNow` → `costCount`/`countPhrase`, `xNum`, `condTrue`, `targetDiscount`), "… spells cost {N} less/more" on permanents (`spellMods`, with `spellMatches` forced true), "This ability costs …" (`abilLess` and any long handler regex in the page that names the wording), Affinity / Delve / Convoke / Improvise. Each line comes out OK, NOT READ (no reader for the wording) or PHRASE NOT UNDERSTOOD (the reader exists, the phrase after "for each" / "where X is" / "if" isn't known). The Monday new-card scan runs it on the week's new cards; run it again after automating a card with a cost line. Rebuild first: it reads `index.html`, not `src/`. As of v4.95 every cost line in the tournament decks and draft sets reads except March of Otherworldly Light's "card exiled this way".

## The match (v4.0)
A game is lost at 0 or less life, 10 poison or a draw from an empty library: the losing player's client notices it (`lossCheck` from `changed()` and `draw()`), and both get the game-over window (`G.go`; messages `gameover`, `goready`, `goback`). The win is recorded only when both click Begin sideboarding. The round clock (`G.mt`) is kept by the host (p1) and sent as `mt`; the guest asks with `mtreq`. It starts at 50:00 once both players have a deck (`deckReady`), keeps running through sideboarding (3:00, `G.sbEnd`), and at 0 offers the end-of-round turns (turn 0 + five, `#turnSign`), then asks who won. Two-player tables only.

## Several targets (v4.04)
An ability with two or more "target" phrases (`tgtPhrases`, `tgtSlots`: Awaken the Inferno, Savage Punch, Practiced Offense) is targeted one phrase at a time: each arrow carries its phrase number (`a.s`), `G.mode.slot` drives the hint and dimming (`tgtSpec(c, slot)`), Esc moves to the next phrase (`tgtNextSlot`). In `simpleEffects` each sentence gets only its own phrases' targets (`SLT`; a sentence without a phrase keeps the previous one's, `slIt` is the one before for "it fights"). Abilities with one phrase, graveyard-card targets, unchosen split halves, "instead" re-statements and hand-drawn arrows (no `a.s`) keep the old behaviour: all arrows for every sentence. When adding a handler that reads `tg`, assume it holds this sentence's targets.

- **v4.112, X targets:** `tgtPhrases` reads "X target …" / "up to X target …" as count `'X'`; `tgtSlots(c)` turns it into the spell's X (`c.x`, else `c.xc`, at least 1) and flags the phrase `xv`, so with X ≥ 2 the phrase keeps asking like "up to two" (`tgtNextSlot`, toast "click another target (2 of 3) (Esc when done)"). Indomitable Creativity is the only baked or draft card it applies to; Kozilek's Command's "up to X target cards from graveyards" still goes through the graveyard picker (`tgtSlots` returns null for graveyard targets).

## Asking the opponent (v4.07)
When an effect makes the other player choose (Fact or Fiction's piles, Intuition, Karn's +1, Council's Judgment's vote), `askOpp(q, fallback)` sends `{t:'q', rid, q}` and waits for `{t:'qa', rid, v}`; the other client runs `answerQ` (a pick box on their screen). `oppChooses(by, title, cards)` wraps the one-card case. Without an opponent (practice) the caster chooses. Effects every player does at once still go through `eachDo` ops plus an `each` message (add new ops to the whitelist in the message handler). Inside `simpleEffects`, a handler that does several sentences at once pushes the later ones onto `skipS` so they are not run again.

## Draft sets (v4.12)
At the top of the `simpleEffects` sentence loop: mode and ability-word labels ("Item — ", "Raid — ") are stripped, except labels older handlers read whole (Landfall, Delirium, Revolt, Threshold, … see the list there) and sentences matching `keepS`; "for each opponent, … target …" loses its opening; simple conditions are judged (`cnd`: attacked this turn, ferocious, hellbent, kicked, N or more creatures, discarded this turn, N or more cards in graveyard) so the rest of the sentence runs or is skipped; "… instead" applies only the difference from the sentence before (`LASTPUMP` for pumps, the text's first "You gain N life" / "deals N damage"). `xNum(phrase)` and `condTrue(phrase)` return null when the table can't work something out (then the sentence is left, or the player is asked). Morph (`morphOf`, `morphCast`, `morphUp`), suspend (`suspendOf`, `suspendCard`, `suspendTick`), outlast (in `abilitiesOf`), living weapon (enter trigger), modular (in `diesTrig`) and changeling (`NOTCT` in `matchesDesc`) are keyword-driven.

## Draft sets, the long tail (v4.16)
- **"This way" and "that creature":** `move()` appends to `ZLOG` (`{c, from, to, at}`, counter `ZSEQ`). Inside `simpleEffects`, `since(to, from)` lists the cards this effect has moved so far (Chrome Courier's "if you put an artifact card into your hand this way", Discerning Taste, Terra's "milled this way"). `tgSnap[id]` holds each target as it was before the effect (counters, attacking, type line, mana value, remaining toughness or loyalty): Bring Low, Rite of the Serpent, Prophesied End, Flay Essence, Violent Echoes.
- **A resolving spell's effects get a fresh object** (`autoResolve({…})` in `resolve`), and the card itself has already gone to the graveyard.
