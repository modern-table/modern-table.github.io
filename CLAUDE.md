# Modern Table: instructions for Claude sessions working in this repo

Repository `modern-table/modern-table.github.io` (the `modern-table` GitHub organization). The game is served by GitHub Pages from `main` at the repo root as https://modern-table.github.io/, so whatever `index.html` is on `main` is what players get. Moved here on 2026-10-17 from an older address, which now only forwards players here and carries their saved decks over (`#import=` in the URL, read by `IMPORTED` in both pages). Keep the project's public face free of personal names: commits are authored by Claude, and nothing in the repo, the pages or the README should name the maintainer.

**Pushing to `main` (the maintainer's standing instruction, 2026-11-22):** once the maintainer and Claude have agreed in chat on a change, Claude builds it, runs the tests and pushes it to `main` without asking again. Pushing to `main` publishes https://modern-table.github.io/ and posts the new NEWS line to Discord: that is the intended, approved result of an agreed change, and the maintainer wants it done by default in every session. This covers ordinary fast-forward pushes of agreed work only; never force-push or rewrite `main`'s history without the maintainer's explicit say-so in that conversation.

## Layout
- `src/app.src.html`: game source (single page; placeholders `/*__DECKS__*/[]` and `/*__PEERJS__*/` are filled by the build).
- `src/decks.txt`: built-in decklists (format below).
- `src/peerjs.min.js`: vendored PeerJS.
- `src/cards.json`: Scryfall data for every card in `src/decks.txt` (plus the tokens they make, keyed `id:<scryfall id>`), built into `index.html` as `BAKED` so the tournament decks need no Scryfall lookups (since v3.42). Written by `tools/make_cards.py <oracle-cards.json>` from Scryfall's Oracle Cards bulk file. The sandbox cannot reach Scryfall, so don't write it by hand: the **Build card data** workflow (`.github/workflows/cards.yml`) regenerates it, rebuilds and pushes whenever `src/decks.txt` changes, every day at 13:23 UTC (retrying when Scryfall answers 5xx), and on "Run workflow". Its commits are by github-actions[bot]. Cards missing from it (new decks before the workflow has run, pasted decks) are still looked up at runtime. The workflow's notice lists names it could not find: a card a decklist calls by another name (Arena's "Through the Omenpaths" names for Marvel cards, e.g. Kavaero, Mind-Bitten = Superior Spider-Man) goes in `src/aliases.txt`, and the game also reads that file for pasted decks. Cards from decks we paste and play (not tournament lists) can be listed in `src/extra.txt` (decklist format); the workflow builds them in too.
- `build.py`: `python3 build.py` writes `index.html`. It drops any deck with fewer than 60 main or more than 15 sideboard cards and refuses to build with fewer than 10 valid decks.
- `index.html`: generated. Never hand-edit; always rebuild and commit it together with the `src/` change.
- **Line comments end the line.** Much of the source is long one-line statements with trailing `// …` notes. When inserting code into such a line, put it before the `//`, never after: anything after a `//` is part of the comment and silently never runs (v4.37 disabled the city's blessing this way; found in v4.55). `build.py` prints `WARNING: … code after a // comment never runs` for lines that look like this; treat any such warning as a bug.
- `tests/`: Playwright tests for the Modern Table (practice game in headless Chromium, local http.server, Scryfall mocked). `python3 build.py && python3 tests/run_all.py` before every release; all must pass. `python3 tests/run_all.py --rev <commit>` runs them against an older build: a test for a fix should FAIL on the build before the fix (if it passes there, the test proves nothing). Add a test file for each fix or feature, and reproduce a reported bug in a test on the previous build before calling it fixed. `test_turnkeys.py` scans the source: every player field set from the turn number must be cleared at a new game (`PER_GAME_KEYS` or `gather()`). `tools/priority_test.py` (two browsers, about 13 minutes) is separate.
- `src/draft.src.html` → `draft/index.html`: the Draft Table (see below). Also generated by `build.py`, which copies it to `night/`, `sealed/` and `cube/` too (see Game Night) and writes `night/decks.json`.
- `draft/sets/*.json`, `tools/make_draft_sets.py`: booster odds per set for the Draft Table.

## The relay (v5.28, Draft v0.38)
When two browsers can't reach each other directly (some home routers, store and guest wifi with client isolation), WebRTC needs a TURN relay. Both pages fetch Metered's Open Relay servers once at load: `relayLoad()` asks `RELAY_URL` (`https://moderntable.metered.live/api/v1/turn/credentials?apiKey=…`, the project's free 20 GB a month plan, signed up with the project's Google account) and puts the answer after `ICE_DEF` (Google's STUN) in `RELAY_CFG.iceServers`. `peerOpts()` gives every Peer that same object as `config`; PeerJS reads `options.config` when each RTCPeerConnection starts, so servers that arrive after the Peer was made still count. A guest dials after `relayReady()` (the fetch, or 3 s, whichever comes first); a failed fetch (6 s timeout) leaves plain STUN and nothing else changes (`RELAY_ST` off | loading | ready | failed). `?norelay` skips the fetch. The key in `RELAY_URL` is the credential's own API key, which Metered calls safe for front-end use; never put the account's Secret Key (Dashboard → Developers) in the repo. If someone abuses the key, add a new credential on Metered's TURN Server page, disable the old one, and swap the new key into both pages. `relayKind(pc)` reads a connection's chosen candidate pair (`getStats`: transport → selected pair → local/remote candidate type), `relayNote(c, done)` calls it after a connection opens (retries a few times); the Modern Table's pill reads Connected directly / Connected through the relay (`G.via`, plus a log line), the Draft Table page's guest pill the same (`VIA`), its host pill "Hosting · N through the relay" (`c._via` on each connection in `conns`). Same code in both pages; keep them in step. Tests: `tests/test_relay.py` mocks `*.metered.live` (the sandbox's proxy refuses it); a real relayed game can only be tried on two devices on one network.

## The phone table (`m/`, phone layer m0.10, 2026-11-24)
https://modern-table.github.io/m/ is the Modern Table for a phone held sideways. Unlisted for now: nothing links to it (it links back to the desktop table), and it has no NEWS line of its own, so nothing goes to Discord. The maintainer's design: Project doc `claude/mobile-design.md` (decisions, the Design canvas prototype). The plan (2026-11-22): step 1 a practice game on the phone (this), step 2 the guided screens (blocking, targeting, the payment window, trigger order), step 3 playing a friend, phone or desktop, step 4 the deck screen; started integrated (same rules, same messages) so a phone can play a desktop.
- **Build:** `build.py` writes `m/index.html` from the finished `index.html` plus `src/mobile.css` (in the head, `<style id="mcss">`) and `src/mobile.js` (after the page's script, `<script id="mjs">`), a viewport that doesn't zoom, an inline script that sets `html.mob`, the title "Modern Table (phone)", and the repo's own relative paths pointed one folder up (`img/coin-flip.webp`, `lgs/`, `night/`, the icons: the build asserts each one is found; a new relative path in `src/app.src.html` must be added to that list). `index.html` gets none of it, so a phone-layer change leaves the desktop page byte-for-byte the same (check with `git diff --quiet index.html`). Every change to `src/app.src.html` changes `m/index.html` too: commit both (the Build card data workflow and the weekly refresh do).
- **Versions:** the phone layer has its own `MVERSION` (`'m0.10'` since 2026-11-24, the voice offer's phone layout; m0.9 on 2026-11-23; m0.2 to m0.8 earlier that day, m0.1 on 2026-11-22, top of `src/mobile.js`), shown in the phone front page's note. Bump it for a phone-layer change; don't bump `VERSION` (that would post to Discord and change the desktop page). The page's `VERSION` and NEWS are the desktop's.
- **How it works:** CSS re-lays the same DOM out (everything scoped to `html.mob`): `--ch` from `100dvh` (four rows of cards and a 28 px bar), left rail of piles, right column (`--rcol` 132 px) with `#mTop` (LOOK `#mLook`, menu `#mMenu`), the players, the stack as a column (newest at the bottom), the big button; the log is a panel (`html.mlog`); hover enlargement and `#about` are off; portrait shows "Turn your phone sideways". `mobile.js` reassigns a few of the page's global functions (allowed for function declarations, never for `const`): `render` (wrapped: `mAfter()` folds lands, paints the hand fan, refreshes open panels), `menu` (`mMenu`: menus become a sheet in `#ctx` with big rows; submenus replace the rows with a Back row; `capture(fn)` collects a menu's items instead of showing it), `aboutCard` (opens LOOK), `showZoom` (off). Top-level names in `mobile.js` share the page's global scope: grep `src/app.src.html` before adding one.
- **Taps:** a capture listener on `window` decides per tap (`tapKind`): cards in `#mLands`, the hand tray, LOOK, my battlefield card (card sheet `openCard`: the big picture plus `primaryFor` (Tap / Untap / Loyalty abilities…) and the card's own `cardMenu` items, without the "Right now" row) and the opponent's (LOOK view `openLook`: picture, Oracle text, RIGHT NOW from the desktop's about panel). Anything else (an arrow mode `G.mode`, choosing attackers, blocking, the stack, piles, windows) goes to the desktop's own handlers untouched. Handled taps stop the event before the page's document listeners and swallow the click that follows at the same spot (it would land on the sheet just opened). Long-press menus are blocked. With LOOK on, a card in a window (`#modal`) is read too (m0.2).
- **Lands:** `foldLands` hides land cards (not creatures) and their attachments and puts a `.mlands` tile first in `#myBack` / `#oppBack`: since m0.2 (the maintainer: pictures over pips) a small picture per land (`.ml`), identical lands grouped with a count (`landGroups`, untapped first), tapped ones turned and dimmed (`.ml.t`), overlapped to fit 55% of the row. The tile or ☰ Your lands opens `#mLands`; tapping a land there runs `toggleTap`, exactly the desktop's click (fetches and lands with several mana abilities, Arena of Glory's exert included, open their menu sheet; a mana ability with a cost needs that mana in the pool first, as on the desktop); its button reads Abilities when the card's own menu has more than tapping (`landExtra`: an `OWN` item not starting Tap/Untap: Mutavault, Fiery Islet, fetches, Arena of Glory), else ⋯; either opens its card sheet. While `#payPanel` is up (`html.mpay`, a MutationObserver) the lands box opens by itself on the left and the payment box sits on the right (the maintainer's payment design), `landSize` sizes the lands so all fit.
- **Hand:** since m0.3 `#mHandBtn`, a fan of every card at the bottom of the board (centred since m0.4, the maintainer: tokens and markers sit in the bottom right corner) (`paintHandBtn`: pictures `.fc[data-hid]`, each card at least `FAN_SHOW` = 52% uncovered, the step shrinking so the fan stays within 48% of the board, at most ±8° at the ends; `.ntime` dims by timing; the count `.hc`). The maintainer's history: m0.1's fan showed only the last three cards and a count ("a disconnected feeling, like I don't even know what's in my own hand"); m0.2's strip of top halves along the bottom made the brain "wonder instead of recognize"; m0.3 is m0.1's look with the whole hand and less overlap. A tap opens `#myHand` itself as a tray (`html.mhand`, with `#mHandHint`); with LOOK on, a tap on a fan card reads it. A tap casts or plays as the desktop's left click does (`handPlay`: modal double-faced and cycling lands keep their menus).
- **Other mana (m0.4, the maintainer: Treasures must be in view while paying):** the lands box also lists my non-land permanents with mana abilities (`manaOthers()`: Treasures, rocks, mana creatures; not attachments) under an "Other mana" separator (`.mlsep`), identical ones grouped as one card with a `.mlcnt` ×N (`landGroups`); a tap is the desktop's `toggleTap` (a Treasure opens its Sacrifice, add … menu). The box opens by itself while paying when there are lands or other mana. `landSize(n, paying, o)` packs the lands and the other mana on separate rows.
- **Screen edges (m0.4, the maintainer):** `m/index.html` has `viewport-fit=cover`, so the phone's hardware covers edges. `applyEdges()` reads the safe-area insets through a probe element (`envInsets`, `#mEnv`) and the camera side from the screen angle (`camSide`: 90 = left, 270 = right; an iPhone reports equal left and right insets in landscape, so only the camera side is kept clear; with no angle both reported insets are used), adds the manual margins (`S.mNotch` auto | off, `S.mCam`, `S.mOth`, `S.mBot` px, following the camera when the phone turns) and sets `--sl` / `--sr` / `--sb` on `html` (`M.edge`). The CSS pads `body`, shortens `--ch` and `#table` by `--sb`, and every fixed panel uses `--sl` and `--rr` (= `--rcol` + `--sr`) instead of 0 and `--rcol`: a new fixed panel on the phone must too. Settings → **Phone** (rows put first in `SETROWS` by `mobile.js`, so only the phone page has them): Camera notch (Keep clear / Use the whole screen, hint `edgeHint()`), Extra margin camera side / other side / bottom (`EDGE_PX`: None, +4 … +32). Re-applied on resize and orientation change. Chromium reports no insets, so tests stand in `envInsets` / `camSide`.
- **Targeting (m0.5, step 2's first screen, the maintainer's design in `claude/mobile-design.md`):** while an arrow mode from my stack card is on (`mTgSrc()`: `G.mode.type 'arrow'`, source on my stack, not Searing Blaze's second step), `tgPaint()` (from `mAfter`) shows `#mTgt` over the phase bar `#mid` (name, Target k of n, "N of M chosen", "tap <phrase>" from `tgtSpec`, the resolution condition, "(or none)"), outlines legal targets `.mtl` (cards in the rows, the stack and the lands box, both player boxes, a `.mlands` tile holding a legal land; `tgtCheck`), rings chosen ones `.mtc` with a `.mttag` TARGET (TARGET k with several phrases), marks the source `.mtsrc`, and lays `#mTgtGo` over `#next`: No target / Done / Next target / Skip target k (`tgDone()`). The maintainer's rules: the table waits for Done even at the most allowed (`M.tg` = the session {from, plain, tq, slot, done}; `tgRearm()` runs inside a wrapped `autoArm` and puts the mode back after the desktop's `finishMode` ended it, so another trigger can't take over first), tapping a chosen target takes it back (it returns to that phrase), with room for one tapping another moves it (an illegal one goes through `tgtGate` first, keeping the old target), a target beyond the most is refused with a toast (`tgMax`: `tgtSlots`, else the single phrase's count from `tgtPhrases`, 99 = any number). Done with none chosen (not "up to") asks Choose a target / No target; fewer than an exact count asks too. Done itself is the desktop's Esc (`mEsc()` dispatches the key), so the next phrase, `ab.nt` on a trigger with none and the rest are the desktop's. "Plain" sessions only (`tgPlain`): Searing Blaze, earthbend, bestow, blink (`ab.auto` included), Auras and face-down cards keep the desktop's one-click flow under the strip. A session that starts with its targets already filled (one opponent for "target opponent") ends the mode at once. Other modes (attach, block, exhold, atktgt…) keep `#modebar`, re-worded by `modebarPhone()` (tap, no Esc) with a `[data-mesc]` Cancel / Attack <name> button. `toast` is wrapped: target toasts are dropped while the strip is up, others say tap, not click, and lose "(Esc …)". The marks (outlines, rings, TARGET tags, player boxes, lands tiles) are drawn by `tgMark(from, arr, sp, tagOf)`, shared with m0.8. `M.preOff` (tests only) sends spells to this screen instead of m0.8's.
- **Blocking (m0.6, the maintainer's design in `claude/mobile-design.md`):** `blkCtx()` (no arrow mode; `blockStep()`: I'm attacked, or `pblockStep()`: I declare Practice's blocks against my attack) gives the blocking side, the attacking side, its arrows and its finish (`doneBlocking()` / `pblockBtn('done')`, so the desktop's own rule checks and logs run). `tapKind` returns `'blk'` for a creature of the blocking side or an attacker of the other side; Clear removes every block. `blkPaint()` (from `mAfter`): `#mBlk` over the phase bar (what to tap, must-block notes, Undo / Clear buttons `data-mb`), `#mBlkGo` over `#next` (No blocks / Done blocking (N)), marks `.mbok` (could block), `.mbsel` + BLOCKER, `.mbon` + BLOCKS, `.mbcan` (attackers the chosen blocker may block, dashed blue), `.mbatk` + BLOCKED / BLOCKED ×N (`.mbtag`); none under `noMotion()`). Since m0.7 (the maintainer: Ocelot Pride's block arrow stayed at its old spot) `blkSlide` also redraws the arrows, which the desktop drew before the rows were re-ordered: at once when nothing slid, else `#arrowG` is hidden during the slide and `drawArrows()` runs once the cards settle (`M.arT`), fading in. - **Targets before paying (m0.8, the maintainer's prototype):** tapping an instant or sorcery in the hand that targets (`preEligible(id)`: an Instant/Sorcery type line, `needsTarget` and `tgtSpec(c, 0)`; not split, adventure, double-faced, X costs, modal "choose …", kicker / overload / spree / escalate / entwine / replicate / splice / buyback / cleave / strive, "divided", graveyard targets, `twoTgt`, blink, Auras, anything `castWays` lists (dash, evoke, alternative costs) or `castTimeWhy` objects to) starts `M.pre = {id, slot, arr:[{b, s?, any?}]}` instead of casting: the card waits in the stack column as `.mcast` (CASTING), the strip `#mTgt` names it with a Cancel button (`[data-mpre="x"]`, `preEnd`), `tgMark` outlines and rings, `#mPreArw` (an SVG over the page) draws an orange line from the card to each target, and `#mTgtGo` reads Cast it / pay <cost> (`mcHTML(d.mc)`, the printed cost), or Next target / Skip target k for several phrases (`preMax`: `tgtSlots(c)`, else `tgtPhrases`). ## Draft Table (`/draft/`)
Booster draft for up to 8 players; bots fill empty seats. Its own version: `const VERSION = 'v0.NN'` in `src/draft.src.html`, bumped the same way. With every bump add a line at the top of `DNEWS` (same file, right under `VERSION`; `['v0.NN','Mon D','what changed']`, written for players): it fills the front page's What's new column (latest six, "See all changes" shows the rest in place). Draft lines don't go to Discord.
- **Hub model:** the host's browser holds the whole draft (`H`), generates every pack and sends each player only their own view (`V`: current pack, picks, pod status, tournament). Guests send `join`, `pick`, `ready`, `result`. Host state is saved in localStorage (`dt_host`) so a reload resumes; guests rejoin their seat by a stored player id (`dt_pid`).
- **Pack odds:** `draft/sets/<set>.json`, generated by `python3 tools/make_draft_sets.py /path/to/sealed_basic_data.json` from https://github.com/taw/magic-sealed-data (weighted pack layouts and sheets; cards are `set:collector_number`, `:foil` suffix for foils). To add a set, add its booster code to `SETS` in that script, rerun it, rebuild. Sets whose draft works differently (Commander Legends, Conspiracy, Unstable, Mystery Booster) are deliberately left out.
- **Cubes:** a pasted cube list goes, cleaned to one card name per line, in `draft/cubes/<code>.txt`; `python3 tools/make_cube.py <code> "Name" draft/cubes/<code>.txt` writes `draft/sets/<code>.json` (`cube:1`, `names`) and lists it under "Cubes" in `index.json` (`make_draft_sets.py` keeps those entries). Bots ignore rarity in a cube.

## Weekly deck refresh (what the Monday scheduled task does)
Goal: replace `src/decks.txt` with top finishers from Modern events of the last 14 days on MTGGoldfish, rebuild, commit, push to `main`.
1. Search: WebFetch `https://www.mtggoldfish.com/tournament_searches/create?tournament_search%5Bname%5D=&tournament_search%5Bformat%5D=modern&tournament_search%5Bdate_range%5D=MM%2FDD%2FYYYY+-+MM%2FDD%2FYYYY&commit=Search` (14 days ago to today). First page only.
2. Pick up to 6 events, newest first: Challenges, Super Qualifiers, Showcases, large paper events. Skip Leagues.
3. For each, WebFetch `https://www.mtggoldfish.com/tournament/ID` for the first 8 rows: place, deck name, pilot, deck id.
4. Choose at most 36 decks: every distinct archetype once first (highest finish), then remaining top-4 finishers.
5. Fetch lists from `https://www.mtggoldfish.com/deck/arena_download/DECKID` (`/deck/download/` is robots-blocked; `/deck/ID` has no list in its HTML). ONE AT A TIME, never in parallel, at most 4 per turn. On HTTP 429 do not retry that page; stop fetching after the second refusal and use what you have. The shell cannot reach mtggoldfish; only WebFetch can.
6. Keep decks from the existing `src/decks.txt` that are still within the last 14 days and were not re-fetched, so a rate-limited week does not shrink the list. Drop decks older than 14 days only if at least 20 decks remain without them.
7. Write `src/decks.txt`, run `python3 build.py`, check its last line reports at least 10 decks and none unexpectedly dropped.
8. Commit `src/decks.txt`, `src/learned.txt` (the build adds the new decks' cards to it), `index.html`, `m/index.html` (the phone table, built from the same page) and `night/decks.json` (Game Night's copy of the tournament decks, written by the same build; leaving it out leaves Game Night on last week's decks, as on 2026-11-16) with message `Weekly deck refresh YYYY-MM-DD (N decks)` and push to `main`. The Build card data workflow then adds the new decks' cards to `src/cards.json` and rebuilds by itself, a few minutes after the push (since 2026-11-16 it also stages `night/`, `sealed/` and `cube/`, and pushes when only `night/decks.json` changed). If the push is refused, do not try other routes; report it.
Colour-code archetype names from MTGGoldfish (WU, UR, WBG) may be replaced with a plain name only when the list makes it obvious.

## Auto-pay (v3.0)
With `S.autoPay` on (the default; ☰ menu toggle), `castSpellNow` and `activate` work out the cost (`castSyms`/`abilSyms`), plan it from the pool (`payPlan`) and either pay at once or open `#payPanel`, which waits while lands are tapped; the card stays in its zone until paid. Alternative costs pass `payCost` (warp, dash, flashback, madness, bestow, harmonize with `less`, Mystical Dispute), `castAlt` pays first, free casts pass `nm`. Mana with a restriction or rider goes to `G.me.smana` (its own row under the pool) and is spent only where `specRule` allows. Since v4.99 auto-pay never spends it by itself: `payFor` opens the window whenever `specFor(ctx)` lists special mana that could pay, and `payPlan` uses only the entries the player clicked into the payment (`PAY.ch.sp`, toggled by `spToggle` from the window's Special mana row or the pool symbol); an alternative-cost button carries the picks on through `G.paySel`. Old tests that cast by hand should set `S.autoPay=false` after the page loads.

## Scryfall requests
Scryfall allows 2 card lookups a second (`/cards/collection`, `/cards/named`, `/cards/search`) and locks a client out for 30 s after a 429 (https://scryfall.com/docs/api/rate-limits). Every request goes through `sfetch` (both pages): one queue, 0.55 s apart, 15 s timeout, 31 s pause and one retry after a 429. Never call `fetch` on api.scryfall.com directly. ## The match (v4.0)
A game is lost at 0 or less life, 10 poison or a draw from an empty library: the losing player's client notices it (`lossCheck` from `changed()` and `draw()`), and both get the game-over window (`G.go`; messages `gameover`, `goready`, `goback`). The win is recorded only when both click Begin sideboarding. The round clock (`G.mt`) is kept by the host (p1) and sent as `mt`; the guest asks with `mtreq`. It starts at 50:00 once both players have a deck (`deckReady`), keeps running through sideboarding (3:00, `G.sbEnd`), and at 0 offers the end-of-round turns (turn 0 + five, `#turnSign`), then asks who won. Two-player tables only.

## Several targets (v4.04)
An ability with two or more "target" phrases (`tgtPhrases`, `tgtSlots`: Awaken the Inferno, Savage Punch, Practiced Offense) is targeted one phrase at a time: each arrow carries its phrase number (`a.s`), `G.mode.slot` drives the hint and dimming (`tgtSpec(c, slot)`), Esc moves to the next phrase (`tgtNextSlot`). In `simpleEffects` each sentence gets only its own phrases' targets (`SLT`; a sentence without a phrase keeps the previous one's, `slIt` is the one before for "it fights"). Abilities with one phrase, graveyard-card targets, unchosen split halves, "instead" re-statements and hand-drawn arrows (no `a.s`) keep the old behaviour: all arrows for every sentence. When adding a handler that reads `tg`, assume it holds this sentence's targets.

- **v4.112, X targets:** `tgtPhrases` reads "X target …" / "up to X target …" as count `'X'`; `tgtSlots(c)` turns it into the spell's X (`c.x`, else `c.xc`, at least 1) and flags the phrase `xv`, so with X ≥ 2 the phrase keeps asking like "up to two" (`tgtNextSlot`, toast "click another target (2 of 3) (Esc when done)"). Indomitable Creativity is the only baked or draft card it applies to; Kozilek's Command's "up to X target cards from graveyards" still goes through the graveyard picker (`tgtSlots` returns null for graveyard targets).
